# ISP-Care Pro App Flow Document

## Onboarding and Sign-In/Sign-Up

When a brand-new user arrives at the ISP-Care Pro web platform, they first land on a clean and minimalistic landing page that briefly explains the value proposition for small and mid-sized retail businesses managing their ISP services. A prominent button invites them to "Get Started," which leads to the account creation flow. On the signup page, the user enters their business name, email address, and a contact phone number. They then select one of the three subscription tiers—Basic, Standard, or Premium—each described with feature highlights. After choosing a plan, the user is directed to the integrated Xendit payment page, where they submit billing details and complete the transaction securely. Once the payment succeeds, the system dispatches a Telegram message to the user’s registered channel with a unique activation link and temporary token. The user clicks that link to set their password for the first time, completing account activation. Returning users access the login page at any time, enter their email and password, and are authenticated via a JWT-based mechanism. A “Remember Me” checkbox allows persistent sessions in the browser or as a Progressive Web App on mobile devices. If a user forgets their password, they click “Forgot Password” and provide their email address. The system sends a reset link via email. Clicking that link brings them to a secure password reset page where they choose a new password. The user can also sign out at any point by clicking their avatar in the header and selecting “Log Out,” which clears their JWT and returns them to the login screen.

## Main Dashboard or Home Page

After signing in, the user arrives at the Executive Dashboard, the default homepage that displays top-level Key Performance Indicators such as Monthly Recurring Revenue, Customer Churn Rate, and number of Open Tickets. A collapsible sidebar on the left lists all major modules—Customers, Map, Tickets, Finances, Reports, and Settings—each represented by a clear icon and label. The top header contains the application logo on the left, an in-app notification bell icon, and the user’s avatar on the right. The center of the page shows a series of card-style widgets summarizing critical metrics and a timeline of recent activities pulled from the audit log. At the bottom of the dashboard view, a horizontal feed highlights any urgent alerts that were also sent via Telegram. The sidebar remains visible on desktop or can be expanded with a hamburger icon on mobile to support the PWA experience. Clicking any menu item seamlessly transitions to the corresponding module.

## Detailed Feature Flows and Page Transitions

### Customer and PPPoE Management Flow

When the user clicks “Customers” in the sidebar, they see a paginated list of all customer accounts for their business. Each row shows the customer’s name, contact information, assigned service plan, and current connection status. To add a new customer, the user clicks “New Customer,” opening a full-screen form where they enter personal details, select a service plan, and specify a connection address. Submitting the form triggers a REST API call to the Mikrotik RouterOS integration to automatically create a PPPoE secret and apply default rate limits. After the router confirms the secret creation, the new customer appears in the table. Editing a customer record updates both the application database and the Mikrotik configuration in real time. Deleting a customer triggers a confirmation modal and, upon approval, disables the PPPoE secret on the router and removes the record. Behind the scenes, a scheduled task polls the router every minute to fetch up-to-date status for each PPPoE secret and synchronizes that status back into the application so the list always reflects live connectivity.

### Geographic Customer Monitoring Flow

Selecting “Map” from the sidebar opens an interactive map view powered by Leaflet.js and OpenStreetMap. Each active customer appears as a green marker, while inactive or disabled connections appear as red or gray markers. Zoom and pan controls allow the user to focus on specific regions. Tapping or clicking on any marker brings up a pop-up card that displays key details such as the customer’s name, service plan, and current status. Within the pop-up, inline buttons let the user view the full customer profile or initiate a support ticket for that customer. Above the map is a horizontal filter bar where users can search by name or filter markers by status or service plan. Technicians who log in see a filtered version of this map that only shows markers tied to tickets assigned to them. Navigating back to the dashboard or any other module is accomplished by selecting the corresponding item in the sidebar.

### Support Ticketing System Flow

Clicking “Tickets” in the sidebar takes the user to the ticketing module, which defaults to a board view showing columns for Open, In Progress, Resolved, and Closed. Each ticket card displays the customer name, issue category, assigned technician, and creation date. To create a new ticket, the user clicks “New Ticket,” selects the customer from a searchable dropdown, chooses an issue category like “No Connection” or “Slow Speed,” and adds a brief description. Once created, the ticket appears in the Open column and a Telegram notification is sent to the assigned technician or admin group. Admins drag the ticket card to assign a technician, which immediately updates the ticket owner and triggers another notification. Technicians log in and see a dedicated Technician Dashboard under the “Tickets” menu that lists only their assigned items along with performance metrics like average response time. As they work, they drag tickets across columns. Each movement records a timestamp and user action in the audit log. After marking a ticket as Resolved, they fill in resolution notes, and then the admin moves it to Closed once they verify the fix. Every status change triggers in-app and Telegram updates.

### Financial Management Flow

When an admin selects “Finances” from the sidebar, the application opens a page with two primary tabs: Transactions and Reports. Under Transactions, the user sees a ledger-style table of income and expense entries grouped by date. A button labeled “Add Transaction” opens a modal where the user enters a title, amount, selects from dynamic categories they’ve defined, and optionally adds notes or attachments. Saving the transaction writes it to the multi-tenant PostgreSQL database and appears immediately in the table. The user can edit or delete entries subject to role permissions. Under the Reports tab, the user picks a date range and category filters to generate Profit & Loss or Cash Flow statements. The resulting report renders as a combination of tables and charts, and the user can click “Export” to download a CSV or PDF. Each export event is logged in the audit trail with user, timestamp, and report parameters.

### Reporting & Analytics Hub Flow

The “Reports” module in the sidebar brings the user to the Reporting & Analytics Hub, which begins with a high-level Executive Dashboard summarizing key metrics across all modules. From there, the user clicks “Detailed Reports” to access prebuilt reports for Customers, Tickets, and Finances. Each category page offers filter controls for date ranges, status, and other relevant fields. After selecting filters, the user clicks “Run Report” and the data refreshes in a table and chart view. For completely custom insights, the user clicks “Custom Report Builder,” which opens a drag-and-drop canvas where they choose data sources, grouping fields, and chart types. Once the user configures a custom report, they can save it under a name, schedule automated email delivery, or export immediately. All configuration and generation actions are recorded in the audit log for compliance.

## Settings and Account Management

The “Settings” area is accessible from the sidebar and only available to users with Super Admin or Admin roles. The first section is Profile Settings, where each user can update personal details like name, email, phone, and profile picture, as well as change their password. Below that is User Management, where Super Admins see a table of all users within their business tenant. They can create new users by filling a form with name, email, role, and optional phone number. They can also edit existing users or deactivate accounts. In the Roles section, Super Admins can review the predefined roles—Super Admin, Admin, Technician—and adjust their permissions if needed. Another part of Settings is Payment & Subscription, where users can view their current plan, upgrade or downgrade between Basic, Standard, and Premium, and manage payment methods via the Xendit integration. A separate CSV Import page under Settings allows Admins to upload CSV files containing legacy customer, ticket, or financial data. The system validates the file format and displays a summary of imported records before committing them. Finally, the Audit Log page lists all significant user actions—like record updates, role changes, and report exports—complete with timestamps, user names, and details, ensuring full traceability. From any of these pages, the user can return to the main dashboard or another module by using the sidebar or the back link at the top of the page.

## Error States and Alternate Paths

If a user enters invalid data into any form—such as an incorrect email format during sign-up or a nonnumeric value for transaction amounts—the system highlights the offending fields in red and displays a clear error message above the form. During payment, if Xendit returns a failure, the user sees an inline notification explaining the issue, such as invalid card or insufficient funds, and can retry without losing entered data. If the application loses connectivity to the server or to the Mikrotik API, a persistent banner appears at the top of the screen indicating that live data might be delayed. The user can still navigate within cached data or retry the action manually. Role-based restrictions are enforced throughout the UI so that if a Technician attempts to access the user management page, they see an “Access Denied” message with guidance to contact an Admin. In case of token expiry, any API call returns a 401 error, triggering an automatic redirect to the login page with a message explaining that the session has expired. After signing back in, the user is returned to their last viewed page.

## Conclusion and Overall App Journey

From the very first page load to daily operations, ISP-Care Pro guides small business owners through a seamless experience. New users find an intuitive signup flow with integrated payment and instant Telegram-based activation. Returning users authenticate quickly and reach an Executive Dashboard that unifies critical metrics. Navigating through customer management, geographic monitoring, ticketing, financial tracking, and reporting remains consistent thanks to the persistent sidebar and clear headers. Role-based access control ensures each user sees only what they need, and advanced features like CSV import, audit logging, and custom report building satisfy administrative and compliance requirements. Error states are handled gracefully, and notifications keep users informed in real time. Ultimately, the platform enables business owners to manage ISP operations, track performance, resolve issues, and make data-driven decisions all in one place.
